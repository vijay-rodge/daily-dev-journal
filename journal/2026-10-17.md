# Daily Computer Science Lesson: Python Object-Oriented Programming (OOP) — Class Methods vs. Static Methods

**Topic:** Object-Oriented Programming (Python)
**Date:** October 17, 2026

---

### 1. Beginner-Friendly Explanation

When writing classes in Python, regular methods operate on a specific instance of that class (using `self`). However, you will often encounter scenarios where you need functions inside a class that either:
1. Need to access or modify the class state itself (not tied to a specific object).
2. Just need to live inside the namespace of the class because they are logically related, but don't need access to *either* the class or the instance.

Python handles these cases using two powerful decorators: `@classmethod` and `@staticmethod`.

*   **`@classmethod`**: Takes `cls` as its first parameter instead of `self`. It can access and modify class-level state. A common use case is creating **alternative constructors**.
*   **`@staticmethod`**: Takes no implicit first argument (no `self` or `cls`). It behaves like a plain function, but resides inside the class's namespace because it performs a task related to the class.

### 2. Correct, Runnable Code Example

```python
class DatabaseConfig:
    # Class-level variable shared across all instances
    DEFAULT_PORT = 5432
    
    def __init__(self, host, port):
        self.host = host
        self.port = port

    @classmethod
    def from_connection_string(cls, conn_str):
        """Alternative constructor using a class method."""
        host, port = conn_str.split(":")
        # cls() calls DatabaseConfig(host, int(port))
        return cls(host, int(port))

    @staticmethod
    def is_valid_port(port):
        """Utility method that doesn't rely on instance or class state."""
        return isinstance(port, int) and 0 < port <= 65535

    def display(self):
        print(f"Connecting to {self.host}:{self.port} (Default port standard: {self.DEFAULT_PORT})")


# 1. Using the regular constructor (Instance method)
config1 = DatabaseConfig("localhost", 3306)
config1.display()

# 2. Using the class method as an alternative constructor
config2 = DatabaseConfig.from_connection_string("127.0.0.1:5432")
config2.display()

# 3. Using the static method directly from the class
print(isinstance(80, int)) # sanity check
print(f"Is port 80 valid? {DatabaseConfig.is_valid_port(80)}")
print(f"Is port 99999 valid? {DatabaseConfig.is_valid_port(99999)}")
```

---

### 3. Explanation of the Code

1. **`__init__` (Instance Method):** Takes `self` to set up instance-specific attributes (`host` and `port`).
2. **`@classmethod` (`from_connection_string`):** Instead of requiring the user to manually split strings and pass individual arguments to `__init__`, this method parses a string `"127.0.0.1:5432"` and uses `cls(host, int(port))` to instantiate the class flexibly. If you subclass `DatabaseConfig`, `cls` ensures the correct subclass is instantiated.
3. **`@staticmethod` (`is_valid_port`):** This function checks if a port number is within valid networking bounds. It doesn't need to know about `self` (the object) or `cls` (the class), but it makes sense to group it inside `DatabaseConfig` because port validation is conceptually tied to database configuration.

---

### 4. Real-World Application

In web development frameworks like Django or FastAPI, configuration classes frequently use `@classmethod` to load environment variables. For instance, a `Settings` class might have a `@classmethod def from_env(cls):` that reads an `.env` file, parses the variables, and returns a fully initialized settings object without cluttering the main initialization logic.

---

### 6. Key Takeaway

Use **instance methods** (`self`) when your code needs object data, **class methods** (`cls`) when you need to interact with the class itself (often for factory/alternative constructors), and **static methods** (no implicit argument) for utility functions that logically belong inside a class namespace.
